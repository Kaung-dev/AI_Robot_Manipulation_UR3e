AIR2 Robot Manipulation — Project Report

Pick-and-place on a randomized 8-hook pegboard with Franka + parallel gripper, using a staged perception → imitation → reinforcement pipeline in Isaac Sim 5.1 / Isaac Lab 2.3.2.

3.2 BC — Vision imitation policy (ACT-inspired)

Architecture (isaaclab_ext/tasks/lift_air2_ur3e_rg2/policy.py):

BCPolicy
├── encoder       FrozenUNetEncoder  (shared, weights frozen)
│                  ─ wrist RGB  → 256-d
│                  ─ board RGB  → 256-d
├── fusion        Linear(2×256 + 25 → 256) ▸ ReLU ▸ Linear(256 → 128) ▸ ReLU
└── action_head   Linear(128 → 16 × 7)          # chunk_size × action_dim

Action chunking (CHUNK_SIZE = 16): each forward pass predicts the next 16 actions. At inference we execute the first action and re-plan next step. This is the same trick that lets ACT (Zhao et al. 2023) stay temporally coherent without a Transformer.

State vector (25-D): joint_pos (9) + joint_vel (9) + last_action (7).

Loss: smooth-L1 on 6-D pose component + BCE on gripper bit, masked over valid chunk steps. 50 epochs.

3.3 RL-IL — PPO warm-started from State-BC

The CNN+chunked vision BC can not be loaded into rsl_rl's actor directly (the actor is a flat state MLP with a single-step head — different I/O shape from the vision BC). So we add a parallel state-only BC trained on the same scripted controller, with the rsl_rl actor's exact architecture:

MLP(input=35, hidden=[256, 128, 64], output=7, activation=elu)
   ── joint_pos_rel (9) + joint_vel_rel (9)
   ── object_position (3) + target_object_position (7)
   ── last_action (7)                                                  total: 35-D

This produces a state-dict with keys 0.weight, 0.bias, 2.weight, 2.bias, 4.weight, 4.bias, 6.weight, 6.bias — bit-identical to runner.alg.policy.actor.state_dict(), so warm-start is a strict load_state_dict(strict=True).

Two critical knobs change in warm-start mode (otherwise PPO destroys the prior in <5 grad steps):

  1. init_noise_std: 1.0 → 0.3 (otherwise random exploration overwhelms the warm-started mean)
  2. empirical_normalization: True → False (state-BC was trained on raw obs; a running normaliser would re-centre observations and invalidate the prior)
Warm-start verification (today's PPO run, killed at iter ~160):
• Mean action noise std: 0.30 ✓ (was 1.0 from-scratch)
• Mean entropy loss: 1.48 ✓ (was 9.92 from-scratch — 85% concentration)
• [bc->ppo] full actor state_dict loaded (8 tensors) ✓
→ mechanism works. Policy is sampling near the BC prior.
Why PPO didn't improve over BC (and what we shipped to fix it):
The base lift task's rewards are tabletop-scale (10cm radii, "object above 4cm = lifted") and don't apply to the AIR2 scene (6m EE-to-object distances, objects spawn on hooks at 1.7m). Result: reward was constant 75 with no gradient.

Fixes shipped (not yet re-trained):
• New reward file isaaclab_ext/tasks/lift_air2_ur3e_rg2/mdp/rewards.py: ee_to_nearest_object (std=0.5m), all_objects_off_hook, all_objects_to_basket (std=0.5m), all_objects_in_basket (radius=0.30m, weight 20).
• Disabled broken terms (lifting_object, object_goal_tracking[_fine_grained]) and rescaled reaching_object std 0.1→0.5.
• Updated scripted_controller.py to actually grasp (7-waypoint sequence per object: approach → pre-grasp → at-object → CLOSE → lift → above-basket → RELEASE) instead of the previous nav-only visual demo.

3.4 ACT comparison

Our pipeline borrows action chunking from ACT (Action Chunking Transformer) but deliberately simpler:

ACT (Zhao et al. 2023)This project
Vision encoderResNet-18 (per-camera)Frozen U-Net encoder bottleneck (shared, 256-d pooled)
Sequence modelTransformer encoder + decoder, CVAE prior2-layer MLP fusion
Action chunkk = 100 (1s @ 100 Hz)k = 16
Temporal ensembleYes (weighted average over overlapping chunks)No (execute first action of chunk only)
Training data~50 teleop demos per task10 scripted demos (current) → 50+ planned
RL componentNonePPO warm-started from state-BC (this project's extension)

Why MLP instead of Transformer? The AIR2 task is short-horizon and the demo trajectories are deterministic (scripted), so the CVAE / Transformer expressivity that ACT needs for multi-modal teleop data is overkill. An MLP trains in minutes, fits in 200 KB, and matches rsl_rl's actor architecture for PPO warm-start. If we move to human teleop demos with stylistic variation (left-vs-right handedness, alternate approach angles), a Transformer + CVAE would be the next upgrade.

6. What's needed to get PPO > BC

Three items, ~1 hour of compute:

  1. Re-collect 50 demos with the new grasping controller (~25 min):
    collect_air2_demos.py … --num_episodes 50 --max_episode_steps 1500 --output datasets/air2_demos_v2
  2. Re-train vision BC on the new demos (~5 min)
  3. Re-train PPO with warm-start using the new reward terms (~30 min for 1000 iters)

All scripts are in place. Expected outcome based on similar IsaacLab tasks: BC ≈ 60–80% pick-place success, PPO + warm-start ≈ 85–95% after fine-tuning.
